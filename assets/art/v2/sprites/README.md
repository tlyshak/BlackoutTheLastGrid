# assets/art/v2/sprites — аркуші ключових кадрів без фону полотна

Похідні копії аркушів `../keyframes/{rey_unarmed,rey_crowbar,dan,guard}_keyframes.svg` (оригінали не
змінювались, лишаються референсом і носієм карт регіонів `../keyframes/*.frames.json`). Саме ці файли
читає рантайм: `scenes/v2/actors/sprite_animations.json` → `tools/build_spriteframes.gd` →
`scenes/v2/actors/*Frames.tres`, а також `HeldGuards/*` у `scenes/v2/levels/Level00_Prologue.tscn`.

Оригінали — це оглядові дошки: фон полотна, смуги-«підлоги» рядів і підписи намальовані **навколо**
поз, і при імпорті як текстура все це потрапляє в кожен регіон `AtlasTexture` — фігура несе темну
прямокутну «картку». Тут лишено тільки пози.

Усі файли: `viewBox="0 0 680 800"`, `width=680 height=800`; імпорт `svg/scale=2.0` (1360×1600), як в
`../keyframes/*.svg.import`.

## Що вирізано (однаково у всіх чотирьох)

| Елемент оригіналу | Скільки | Чому |
|---|---|---|
| `<rect width="680" height="800" fill="#0d1018">` — фон полотна | 1 | і є «картка» |
| `<rect x="0" y="{160,360,560,760}" width="680" height="8" fill="#151212">` — смуга підлоги ряду | 4 | лежить під ногами поз (регіони доходять до y+3), давала темну смужку по низу кадру |
| `<text>` — заголовки рядів і підписи поз | 18–21 | підписи, не пози (ThorVG у Godot їх і так не малює) |
| `<metadata>` (c2pa) — лише у `dan_keyframes.svg` | 0–1 | бінарний маніфест, для похідної недійсний |

## Що лишено
- `<title>` (з суфіксом «sprite sheet without the board background»).
- Єдина група поз `<g stroke="#0b0909" stroke-linecap="round" stroke-linejoin="round">` — **дослівно**,
  разом з тінями-еліпсами під ногами (вони частина пози). Геометрія не змінена, тому карти регіонів
  `../keyframes/*.frames.json` (bbox, `origin`, `margin`, `feet_y_per_pose`) валідні для обох файлів.

Перевірено растеризацією (`Image.load_svg_from_string`, ×2): для всіх 60 поз чотирьох аркушів bbox
чорнила в регіоні похідної == bbox «не-фонових» пікселів у регіоні оригіналу, чотири кутові текселі
кожного регіону прозорі, поза регіонами чорнила немає — крім `guard/knockback`: кінчик кийка виходить на
~5 px правіше свого регіону (x 486–491, y 444–454 viewBox) і в оригіналі, і тут — це тіснота карти
регіонів, не вирізки.

## Як відтворити
```
python tools/derive_sprite_sheets.py            # переписує sprites/*.svg з keyframes/*.svg
python tools/derive_sprite_sheets.py --check    # нічого не пише, перевіряє, що sprites/ == похідна keyframes/
godot --headless --path . --import
godot --headless --path . -s tools/build_spriteframes.gd
```
Скрипт працює структурно: кожен верхньорівневий елемент має бути або відомим елементом дошки
(фон/смуга/підпис за тегом, розміром і кольором), або групою поз; інакше — помилка, а не вирізка
навмання. Новий аркуш від художника з іншим макетом → розширити правила в `classify()`.
Тест `tests/smoke/v2_spriteframes.gd` вимагає, щоб таблиця анімацій брала аркуші звідси і щоб кути
кожного регіону були прозорими.
