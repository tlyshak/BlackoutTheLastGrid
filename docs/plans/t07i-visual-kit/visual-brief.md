# Спільний візуальний бриф — T-07i (доопрацювання прологу)

Спільний контракт для задач **T-07i-a**, **T-07i-b**, **T-07i-c**. Обов'язковий до прочитання
кожним агентом, що торкається візуалу в цих задачах. Джерело істини по стилю — `GAME_DESIGN.md` §6.

## Рішення автора (2026-09-09)
- **Арт — процедурний, у движку.** Ніяких файлів-картинок: `Polygon2D`, `Line2D`, `GradientTexture2D`,
  `CanvasItemMaterial`/`ShaderMaterial`, `GPUParticles2D`, `PointLight2D`. `assets/art/` лишається
  порожньою; заборона CLAUDE.md на створення арт-ассетів **не знімається** — ми не створюємо
  ассети, ми будуємо векторну графіку в сценах.
- Це має бути **краще за прямокутники**: силуети з упізнаваною формою (голова, тулуб, руки, ноги),
  обводка, плоскі тіні — принцип SoR4, а не його образи.
- Слоти під майбутній мальований арт зберігаються: вузол `Visual/Sprite` (`AnimatedSprite2D`)
  лишається в кожному персонажі, щоб пізніше підмінити рігу на спрайт-лист.

## Контракт ріга персонажа (створює T-07i-b, споживає T-07i-c)
Сцена `scenes/actors/CharacterRig.tscn` + `scripts/actors/CharacterRig.cs`, вставляється як дитина
вузла `Visual` існуючих персонажів. Не є `CharacterBody2D` — це чиста графіка.

```
Visual/                       (Node2D, лишається на місці; position, scale.x — фліп)
  Rig            CharacterRig (Node2D)
    LegBack      Polygon2D
    ArmBack      Polygon2D
    Torso        Polygon2D
    LegFront     Polygon2D
    Head         Polygon2D
    Face         Polygon2D    (напрямок погляду)
    ArmFront     Node2D       ← точка, до якої кріпиться кисть
      Fist       Polygon2D    ← замінює PH_Fist; шлях анімацій оновити
    Outline      Line2D       (опційно, спільна обводка силуету)
  Sprite         AnimatedSprite2D  (лишається порожнім слотом під майбутній арт)
```
`[Export]` у `CharacterRig`: `SuitColor`, `SkinColor`, `OutlineColor`, `Build` (`Slim`/`Normal`/`Heavy`),
`OutlineWidth`. Персонажі відрізняються **кольором і статурою**, не окремими сценами.

**Сумісність, яку не можна зламати:** методичні треки `HitboxOn`/`HitboxOff` в анімаціях ударів;
`Player.PlaceholderBody`/`Sprite`/`Visual` `[Export]`-и (шляхи оновити разом зі сценою);
`Visual/Hitbox`, `Visual/Hurtbox` лишаються дітьми `Visual` на своїх позиціях (стрибок піднімає
хертбокс — рішення автора з T-B01); декаль-тінь `PH_Shadow` лишається дитиною кореня, не `Visual`.

## Шари глибини (єдина z-структура рівня)
| z_index | Шар |
|---|---|
| −100…−60 | `ParallaxBackground` — порода, далекі опори, силуети конструкцій |
| −40 | фон кімнати, стіни, стеля |
| −20 | підлога, декалі, освітлені плями |
| −10 | тіні під персонажами |
| 0 | ігрова площина: герой, вороги, пропи (`y_sort_enabled` на батьківському вузлі) |
| +20 | ефекти удару, іскри, пил |
| +40 | передній план (силуети опор, труби, які камера проходить повз) |
| CanvasLayer | темрява (`CanvasModulate`), віньєтка, HUD, кат-сцени, меню |

## Що робить кожна задача
- **T-07i-a** — обгортка гри: повний екран, головне меню, налаштування, пауза. Візуал меню
  використовує палітру і той самий шрифт/тему, що HUD (`scenes/ui/HudTheme.tres`).
- **T-07i-b** — `Palette.cs`, `CharacterRig`, переведення `Player`, `Guard`, `Dummy` і фігури Дана
  на ріг, анімації idle/walk/jump/attack/hurt/KO на рігу.
- **T-07i-c** — наповнення і подача прологу: параллакс, фактури, пил, ефекти удару, полірування
  темряви й камери, дрібні покращення іграбельності.
